---
title: Security grades
description: What A to F mean, what an ungraded scan means, and why an unscanned server is never shown as safe.
---

Every marketplace listing carries a trust grade, or says it has none. The grade comes from the same
`grade_scan` function the CLI and the agent posture view use, computed from the same scan the
dashboard reads. There is no marketplace-specific rubric.

## The letters

| Risk | Grade | Label | Recommended action |
| --- | --- | --- | --- |
| 0–9 | A | Trusted | Allow |
| 10–24 | B | Generally safe | Allow |
| 25–49 | C | Caution | Require approval |
| 50–74 | D | High risk | Require approval |
| 75–100 | F | Do not use | Block |

The number beside the letter is the **risk score**: 0 is clean, 100 is "do not use". Two numbers
on purpose: the score is the technical detail, the letter is the decision.

A listing can also show **no letter at all**, rendered as `?`. That is not a bad grade; it means
the scan behind it could not produce a grade, usually because the server's tools could not be
enumerated. See *Scan states* below.

## What moves a grade

Findings, weighted by severity: Critical 25, High 15, Medium 8, Low 2, Info 0, capped at 100 so
a pile of minor findings can never out-rank one serious one. One open critical finding is 25
points on its own, which lands a listing in C at best.

The properties that used to be scored separately — declared execution capability, write
capability, missing authentication, plaintext transport — are now findings in their own right
(AS-002, AS-006, AV-002), so they move the grade through the same arithmetic as everything else
rather than through a second parallel rubric. One model, one number.

An unknown never counts *for* a grade. A server whose tools could not be read does not receive a
flattering letter for having produced no findings; it receives no letter. "We didn't look" is
not "there was nothing to find."

## Scan states

The letter alone is never the whole answer. Every grade is shown with the state of the scan behind
it, and the four states mean different things.

**Complete.** The scan finished, every core stage ran, the server's tools were successfully
enumerated, and the version scanned is the version currently published. This is the only state
where the grade is drawn in colour.

**Partial coverage.** The scan finished but at least one core scanner stage did not run — a tool
was missing, Docker was down, the network was unreachable. The findings are real. The *absence* of
findings in the stages that did not run proves nothing, so a partial scan is never presented as
clean.

**Outdated.** The grade was earned by an older version than the one currently published. Aevrin
shows which version the grade covers and which version is current, and does not apply the old
letter to the new release.

**Not yet scanned.** There is no evidence. This is not a statement that the server is unsafe, and
it is emphatically not a statement that it is safe. It means Aevrin has not looked.

## Why security belongs to a version

A grade is stored against a specific version string, never against the listing in general. When a
publisher releases v1.5.0, that version is recorded immediately as unscanned; v1.4.2's B does not
transfer to it.

This is the single most important structural decision in the marketplace. A catalogue that showed
last month's grade beside this week's release would be publishing a claim it had no evidence for.

## Where a grade came from

A listing used to show three sub-scores (code security, MCP surface, dependencies). Those are
gone, along with the general code-security scanning they described. Three opaque numbers were a
worse answer to "what earned this grade" than the findings themselves now are: every finding
carries a rule id, the evidence that made it fire, and the tools it affects, so the list *is* the
breakdown.

## Badges

| Badge | Meaning |
| --- | --- |
| Aevrin scanned | A real scan produced this grade |
| Grade A / Grade B | Scanned, fully covered, current version |
| Needs review | Graded C or D |
| Partial coverage | A scanner stage did not run |
| Outdated scan | The grade covers an older version |
| Unscanned | No security evidence |

There is deliberately no "Aevrin Verified" badge. Verification would need documented criteria, and
a trust badge whose criteria nobody has written down is a claim the product cannot stand behind.

## Grades are not popularity

Stars, forks and download counts are shown in a separate panel, in muted type, below the grade.
They are labelled for exactly what they measure — "GitHub stars", never "users". A download count
includes every CI run that ever installed the package.

None of them is a security signal, and none of them can raise a grade.
