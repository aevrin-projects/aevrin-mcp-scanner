The Aevrin Registry is a curated catalogue of reusable engineering capabilities: MCP servers,
skills, prompts, agents, templates, repositories, tools and more. People browse it at
[app.mcp.aevrin.net/marketplace](https://app.mcp.aevrin.net/marketplace). AI agents query it over
MCP (see [Using the registry from an agent](/agents)).

An administrator decides what is published. Nothing reaches the public registry automatically:
not a server synced from the official MCP Registry, and not a user's suggestion.

**The registry is for discovery.** Publishing an item is curation, not a security verdict: Aevrin
does not scan, grade or security-check anything it lists, and no item shows a grade or a scan
result. To check an MCP server you found here, scan it yourself (see
[Scanning a server you found](#scanning-a-server-you-found)).

## What an item is

Every item has a type. The type decides what the item page shows and what an item needs before it
can be published.

| Type | Needs, before publishing |
| --- | --- |
| MCP server | A package, a hosted endpoint or a repository |
| Prompt | The prompt text |
| Skill | Its instructions |
| Repository, template | The repository URL |
| Agent, tool, component, workflow, library, CLI, backend, frontend, infrastructure, product, integration, dataset, documentation, other | A repository, a homepage, or usage or documentation text |

Every item also needs a title and a description, because those are what search matches and what an
agent reads to decide whether the item is relevant.

## Scanning a server you found

An MCP server's page has a **Scan with Aevrin** action. It opens Aevrin's own scan page with the
server already filled in: its GitHub repository if it has one, otherwise its hosted endpoint. If the
server is published only as an npm or PyPI package, the page shows the CLI command instead, for
example:

```bash
aevrin scan mcp "npx -y @scope/server"
```

The scan that runs is the same one as any other Aevrin scan, in your account and against your plan's
quota, and its result is yours, on your scans page. Nothing about it is written back to the
registry. If you are signed out, you are asked to sign in first and then returned to the prefilled
scan page. See [Scan targets](/targets) and [the CLI](/cli).

Other item types (prompts, skills, templates and the rest) have no scan action: there is no scanner
for them.

## Where MCP servers come from

Aevrin reads the [official MCP Registry](https://registry.modelcontextprotocol.io), a public list
of server metadata (name, description, version, repository, packaging). It does not fork the
registry, mirror it as authoritative, or replace it. It adds three things the registry
deliberately leaves out: curation, ranking, and ready-to-copy client configuration.

Servers read from the registry arrive as **drafts**. An administrator chooses which ones to
publish: one at a time, or in bulk for the drafts that meet a stated quality bar (see
[Administration](/admin#publishing-qualifying-drafts)).

Every item shows its provenance:

| Source | Meaning |
| --- | --- |
| Official MCP Registry | Published to the registry by its author, whose namespace the registry verifies via DNS or GitHub |
| Suggested by a user | Proposed by an Aevrin user and published by an administrator |
| Added by Aevrin | Added by an administrator |

A listing is not an endorsement and not a security assessment. It means an administrator chose to
publish the item.

## What the registry adds

**Transparent ranking.** "Recommended" is a fixed formula over signals you can see, not a model.
See [Searching](/search).

**Honest popularity.** Stars, forks and downloads are named for what they measure. None of them is
a count of users, and none of them is a security signal.

**Curation.** Titles, descriptions, categories, technologies and use cases are maintained by an
administrator, who can also relate items to each other.

## What it does not do

- It does not scan, grade or security-check anything it lists. Scan a server yourself before you
  rely on it.
- It does not process payments for third-party servers. A paid server links to its publisher's own
  pricing page and nothing more.
- It does not claim compatibility a server has not declared. If a server declares no transport
  Aevrin recognises, no install option is offered.
- It does not state that a server is free unless its licence and packaging establish that.
  Anything else reads "Not stated".
- It does not install anything on your machine or change your agent's configuration. It gives you
  configuration to copy. See [Installing](/install).

## Update schedule

A scheduled job runs roughly weekly and:

1. Pulls servers changed since the last successful run from the official MCP Registry. New ones
   are stored as drafts.
2. Records any new versions in each item's version list.
3. Refreshes GitHub and npm metadata for the items whose data is oldest.
4. Recomputes ranking scores.

It never overwrites what an administrator curated. If the official registry is unreachable, the
Aevrin Registry stays online with what it has. If GitHub is unreachable, the previously stored star
count is kept rather than overwritten with zero.
