---
title: Suggesting an item
description: How to suggest an MCP server for the registry, and what happens to a suggestion afterwards.
---

Any signed-in user can suggest an MCP server at
[app.mcp.aevrin.net/marketplace/submit](https://app.mcp.aevrin.net/marketplace/submit). A
suggestion goes to an administrator. It is never published by being suggested.

Other item types (prompts, skills, templates and the rest) are added by administrators.

## You supply a URL. Aevrin derives the rest.

The form has one required field: a public GitHub repository URL, or a public HTTPS MCP endpoint.

Everything else (name, description, licence, stars, README, packaging, categories) is read from the
source. You are not asked to type metadata about software, because a form that accepted typed
metadata would accept whatever anyone chose to claim about software they do not own.

## What is refused, and why

- **Anything that is not HTTPS.** No `http://`, no `file://`, no `javascript:`.
- **Anything internal.** Loopback, private ranges, link-local, `.internal`, `.local`, and cloud
  metadata endpoints. Suggested URLs go through the same SSRF guard the live-target scanner uses.
- **Credentials in the URL.** `https://user:password@host` is rejected.
- **Duplicates.** If the server is already in the registry, report a problem with the existing item
  instead.

Nothing you suggest is executed at this point. Aevrin reads the source; it does not run install
scripts, postinstall hooks, or MCP commands.

## The flow

1. You suggest a URL.
2. Aevrin derives the metadata from the source.
3. An administrator approves or rejects it.
4. If approved, it is published.

Approval runs the same check as an administrator's **Publish**: the item must be complete for its
type. Publishing is curation, not a security verdict: the registry does not scan what it lists.

## Status

Your suggestions are listed on the same page with their state:

| Status | Meaning |
| --- | --- |
| In review | Waiting on a decision |
| Published | Live in the registry |
| Not accepted | Rejected, with the reviewer's reason shown |

A rejection always carries a reason. A decision delivered without one is not a decision anyone can
act on.
